# status.md — 当前状态与后续方向

> 会话间交接快照：已实现能力清单（现状）、遗留待办、人工验证清单、未来方向。
> 各领域实现的**细节陷阱**见 [backend.md](backend.md) / [media.md](media.md) / [frontend.md](frontend.md)。

## 1. 已实现能力（现状）

- **认证与会话**（ADR-002）：单口令 + 会话 Cookie；多终端独立会话，登出只清自身。
- **泛用文件浏览器（「文件」页签，2026-08 重构）**：绝对路径浏览所有本地盘符（fixed/removable，排除
  网络盘）、pin 常用路径、剪贴板式剪切/拷贝/粘贴/重命名/删除（copy/move 走 jobs 后台任务带进度，
  删除永久 + 强确认）；**多媒体源标记**（`media_sources`）：任意目录标记为源即入队全量扫描，视频自动
  入库；取消标记不删库；源列表展示离线/扫描中状态、行内可手动重扫。文件内容不入库，目录跳转后端
  实时读取。详见 [backend.md](backend.md) §10 / [frontend.md](frontend.md) §1.1。
- **扫描与索引**：多媒体源全量扫描，指纹 `(file_id,size,mtime)` 增量、**file_id 全局匹配**（跨源移动
  保持身份）、路由表跳过嵌套子源子树、源根不可达时中止且不动库、HIDDEN/SYSTEM 条目不索引；`jobs`
  队列 + Worker（probe/thumbnail/scan_source/remux，崩溃恢复）；**原子化**：单视频元数据单条提交、
  「把一组单集聚成系列」按 show 单事务提交。
- **长时任务系统（jobs 独立组件）**：用户可见长时任务（扫描/重封）带展示名与进度；扫描按文件数上报
  确定进度、重封解析 ffmpeg `out_time_us` 上报进度、未知时长任务显示不确定条；前端 header「后台任务」
  按钮 + 弹出面板（JetBrains 风格，`RefreshCw` 有任务时转圈）。扫描锁定机制（storage_busy）已随
  存储卷模型移除。
- **播放**：能力探测三层（直连 Range / HLS 按需转码 / 兜底）；live 型增量 HLS 转码（单飞、内存快照、
  `.done` 标记、no-store）；封面；侧边 `.srt/.vtt/.ass` 字幕；Vidstack 播放器 + 本地 hls.js。
- **历史续播**：`history` 表（user=`local`）；前端 10s 节流保存、进入 seek（距片尾 20s 内不续播、播完归零）。
- **媒体库（单集/系列）**：统一「单集（`show_id IS NULL`）+ 系列（`seasons` 行，一季一个系列，无电影/tv
  结构类型，`kind` 恒 `tv`）」；成员位次排序允许缺失；`series_links` 弱关联（同 show 相邻季自动关联 +
  手动增删）；首页行（继续观看/最近添加）。集合子系统已整体移除（2026-08）。
- **搜索**：FTS5（`videos_fts` external content + 触发器，bm25 排序），`search_text` 由 store 层维护。
- **元数据（手动）**：ffprobe 自动填充技术字段（时长/编码/分辨率）；标题/简介/评分/标签等由手动 PATCH
  编辑；封面 `POST /api/videos/{id}/cover` 落盘。**刮削子系统（TMDB 在线 + NFO 侧边文件）已整体移除
  （2026-08）**。
- **前端**：多 Router 页签 keep-alive、栏位栈视频库、Vidstack 播放器、响应式 UI、重封页签——详见
  [frontend.md](frontend.md)。

## 2. 遗留 / 待办

- **多媒体源变更监控未做**（ADR-012 下阶段）：无 fsnotify 监视，源内文件增/删/迁移不会自动反映到库，
  需手动重扫。
- **非源目录手动入库（离散资源）未做**（videos.source_id 已预留 NULL）。
- **上传/下载/新建文件夹未做**（旧 Explorer 移除后暂缺，文件页签仅有剪贴板类操作）；仅列表视图
  （网格视图已放弃）；剪贴板为前端内存态（刷新即失）；大文件复制/移动依赖后台任务（fscopy/fsmove），
  若 worker 繁忙会排队等待。
- HLS 仅单一路码率（`-hls_time 10`，无自适应多码率）；嵌入字幕轨道抽取未做（仅侧边字幕文件）。
- 前端无 Vitest 测试（`package.json` 无 test script）。
- `docs/decisions.md` 尚未创建（plan 附录 A）。
- 单集/系列**手动归组 UI** 已做：`VideoMetaPanel` 的 `SeriesAssign`（选系列/集号，PATCH
  `show_id`/`season_number`/`episode_number`，空串移出系列）；系列关联增删在 `SeriesDetailPage`。

   8.5 嵌套源路由表：把 `C:\Videos` 和 `C:\Videos\Movies` 都标记为源，各自扫描互不重复；子源区域只
       由子源扫描。
   8.6 跨源移动：把视频文件从源 A 移动到源 B，重扫 B 后库中仍是同一条记录（历史/手动元数据保留），
       A 重扫不会把它删成两条。
   8.7 离线状态：源目录（如移动硬盘根）被拔出/改名后，左侧源行显示「离线」徽标；手动重扫报错但**库
       内容不动**；插回后重扫恢复正常。
   8.8 **严格自动归组 + 系列 ↔ 物理目录严格对应（2026-08）**：
       a. 同一目录 ≥2 个 `Show.S01E01`/`第01集` 风格文件 → 自动成一个系列（同季多集）；**目录内不能有
          任何不匹配的视频对象**——混入一个 `Foo 特别篇.mkv` 之类不匹配文件时**整目录不自动归组**；
          `2+2` 两个系列混放、`Bar 1/Bar 2` 旁放一个无关文件也**整目录不归组**（全部保持单集）。
       b. `Show/Season 1/` 下 ≥2 个文件自动成系列（季号取目录、剧名取上级目录）；`Show/第01集.mkv` 这类
          剧名在父目录的也成系列；目录里只有 1 个文件**不成系列**。
       c. 无编号但同前缀系列（`XX冒险记：北京/上海/广州`）自动成系列，按文件名序排列；`720p/x264/10bit`
          等发行后缀、文件名里的年份（如 `Foo 2011`）不影响归组。
       d. 系列详情只列出实际成员，**不再出现「第 X 集缺失」占位**（编号 1、3 缺 2 只显示 1、3 两行）。
       e. **无电影/tv 类型**：`Bar 1/Bar 2`（Part/数字后缀）也按普通系列归组（每部一季、自动关联），
          界面统一显示「系列剧集」；电影/tv 区分后续走标签。
       f. 非多媒体文件（字幕 .srt/.ass、nfo、封面等）可在系列目录里任意混放，不影响归组。
